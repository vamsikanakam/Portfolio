03 / UX Strategy & Design · Five Planes

Implemented 5S framework from a UX perspective to bridge the Gap between Business Strategy & Actual Visual Design

01 · Strategy — Why?

Goal: Improve weld traceability, real-time fault response and 100% weld-spot monitoring.

Method: Translate production problems into focused information and workflows that supervisors and operators could use to detect, investigate and counter faults with minimal time loss.

02 · Scope — What?

Define what the system needed to capture, monitor and make actionable: weld parameters for every spot; robot and weld-body information; fault and downtime information; shift/date/time tracking; MOS-linked spot information; Spot-0 Status; historical traceability; and countermeasure/parameter-change tracking.

03 · Structure — How is information organised?

Structure information so users could move from production line → sub-assembly → robot → weld body → weld spot and access corresponding parameters and fault information.

MOS integration enabled users to identify where a spot was applied, which sub-assembly it belonged to and which robot performed it.

04 · Skeleton — How does the user navigate?

Define navigation around the investigation workflow: select line/sub-assembly → shift/date/time → robots and weld bodies → individual weld information → faults → parameters and countermeasure actions.

DAP/design review with Vendors validated the proposed structure and interactions before manufacturing.

05 · Surface — What does the user see?

Customize the WICS interface so required production information could be presented clearly through dashboard, monitoring views, navigation hierarchy and information states defined for the Maruti use case.

05 / Insight-Driven RCA

When WICS exposed the symptom, I drove the investigation to the root cause.

Production issueWICS detection & traceabilityManagement escalation + approvalPFMEA-based prioritizationQARoot cause15-day action planClosure

Symptom: A recurring weld-related production issue was flagged by WICS. The underlying cause was not yet known and required investigation.

Root-cause example

WICS exposed a recurring high-resistance fault.

Investigation traced the issue to a datum-hole mismatch between two parts, creating a gap during fitment and affecting welding conditions.

Before WICS, the robot fault was not being diagnosed effectively because welding parameters were not being finalized robustly against actual part variation. WICS made the fault visible and traceable; the subsequent QA/vendor investigation identified the underlying part-fitment issue.

What I owned

Escalated the production and efficiency impact to management and secured approval to act.

Prioritized issues using criticality, frequency and risk through a PFMEA-based approach.

Mobilized In-house QA and Vendor QA to identify and address root causes.

Defined a 15-day corrective-action plan with roles, responsibilities and timelines.

Drove execution to closure while protecting running-body accuracy.
